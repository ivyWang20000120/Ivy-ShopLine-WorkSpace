# 用户手册模板

一份可直接复用的 Word 用户手册模板，抽离自实际项目手册的通用结构与视觉样式。当需要为新产品/插件/系统撰写用户手册时，基于本模板填充内容，保持章节骨架和样式不变。

## 何时使用

- 用户明确要求"写用户手册/操作手册/使用说明书"，且希望是正式的、可交付的Word文档；
- 用户提到"参考之前的格式""按标准手册结构写"；
- 需要文档包含：产品简介、核心功能、使用前准备（前置条件）、分模块的功能说明与操作步骤、字段/数据对照表、常见问题等内容。

如果用户只是想要一段简短的、内嵌在对话里的说明文字（不需要交付Word文件），不必套用本模板，直接文字回答即可。

## 模板文件

`assets/用户手册模板.docx` —— 已经写好完整章节骨架与样式，所有需要替换的内容用【】占位符标出。

## 模板包含的章节骨架

1. **产品简介**
   - 1.1 核心功能（3-4条加粗功能名+说明的列表）
   - 1.2 关键字段/数据对应关系表（两个系统之间的字段映射，如不适用可删除）
2. **使用前准备**（前提条件编号列表 + 橙色"重要提示"框）
3. **主要功能**（每个功能模块一个3.x小节，模板给了6个典型模式示例，可按实际功能数量增删）
   - 3.1 连接/授权配置类（说明+截图占位+编号步骤+提示框）
   - 3.2 基础数据同步类（多个Tab分别说明同步操作）
   - 3.3 映射/绑定配置类（添加操作步骤 + 使用规则与限制列表 + 提示框）
   - 3.4 频率/定时任务配置类（配置步骤 + 工作原理说明）
   - 3.5 任务/日志列表类（字段说明表格）
   - 3.6 反向同步/特殊场景处理类（事件监听流程）
4. **常见问题 FAQ（可选）**（现象/可能原因/处理建议三栏表）

## 保留的Word样式规范

复用模板时**不要**改动以下样式规则，直接沿用模板里已经设置好的格式：

| 元素 | 样式 |
|---|---|
| 一级标题（如"1. 产品简介"） | Arial，编号蓝色(#3370FF)，标题文字加粗黑色，18pt |
| 二级标题（如"1.1 核心功能"） | Arial，编号蓝色(#3370FF)，标题文字加粗黑色，16pt |
| 正文 | Arial 11pt，1.2倍行距 |
| 提示框（重要提示/操作提示/注） | 橙色边框(#FFBA6B) + 浅橙底色(#FFF5EB)的单元格表格，标签加粗 |
| 截图占位 | 灰底加粗文字："[ 此处插入截图：xxx ]" |
| 操作步骤 | 阿拉伯数字编号列表 |
| 字段/数据说明 | 表头浅灰底加粗的表格 |

## 使用流程

1. 复制 `assets/用户手册模板.docx` 到工作目录，作为新手册的起点（不要直接从零创建docx）。
2. 按 `/mnt/skills/public/docx/SKILL.md` 的方法解压编辑，或直接用 docx-js 按模板样式规则重新生成——但**结构和样式必须与模板保持一致**。
3. 逐节替换【】占位符：
   - 与用户确认产品名称、核心功能点、前置条件、各功能模块的实际操作步骤、字段说明等内容；
   - 若某个3.x示例模块（如"反向同步场景"）在新产品中不适用，直接删除该小节；若功能模块超过6个，复制某个最相近模式的小节结构继续编号（3.7、3.8...）。
   - 若用户提供了实际截图，替换掉"[ 此处插入截图 ]"占位段落，插入真实图片（参考docx skill的ImageRun用法）。
4. 删除封面页的"模板使用说明"斜体提示段落（这段仅供协作时参考，不应出现在最终交付文档中）。
5. 生成后按docx skill的验证步骤转PDF截图检查排版，再交付给用户。

## 注意事项

- 不要为了"创新"随意更改标题颜色、字号、提示框样式——模板样式的价值就在于跨项目保持一致，方便用户日后维护多个产品的手册库。
- 若用户的产品结构明显不同（例如没有"仓库/地点映射"这类概念），仍应保留大的四段式骨架（简介→准备→功能→FAQ），只调整3.x小节的具体模块划分。
- 内容部分（案例、步骤文字）必须完全替换为新产品的真实内容，不能遗留原手册（领星ERP/Shopline）的示例文本。
